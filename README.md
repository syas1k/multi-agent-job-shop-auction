# Multi-Agent Job Shop Auction

Исследование мультиагентной системы с аукционным механизмом
для динамического календарного планирования в задаче
**Job Shop Scheduling (JSSP)**.

## Идея

Классический JSSP решается централизованно (например, методами
оптимизации или эвристиками). В динамической постановке задачи
(поломки станков, новые заказы, срывы сроков) централизованное
управление становится слишком жёстким.

В этом проекте предлагается **децентрализованный подход**:
- каждая **работа** — это агент (`JobAgent`);
- каждый **станок** — это агент (`MachineAgent`);
- координацию выполняет `ManagerAgent`.

Когда станок освобождается, он **объявляет аукцион** среди готовых
к обработке работ. Работы подают ставки на основе своего приоритета
(критический путь, tardiness, makespan). Побеждает лучшая ставка.

## Архитектура

```
     ┌──────────────────┐
     │  ManagerAgent    │  координирует раунды
     └────────┬─────────┘
              │
     ┌────────┴─────────┐
     │                  │
┌────▼─────┐      ┌─────▼────┐
│ Machine  │◄────►│  Job     │
│ Agent    │ auction│ Agent  │
└──────────┘      └──────────┘
```

- **JobAgent** — представляет работу, знает свои операции и сроки,
  подаёт ставки на аукционах.
- **MachineAgent** — станок, объявляет аукцион, выбирает победителя.
- **ManagerAgent** — запускает раунды, разрешает конфликты,
  собирает метрики.

## Метрики

- **Makespan** — время завершения всех работ.
- **Total tardiness** — суммарное опоздание.
- **Загрузка станков** — эффективность использования.
- **Сходимость аукциона** — число раундов до равновесия.
