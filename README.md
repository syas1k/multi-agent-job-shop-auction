# Multi-Agent Job Shop Auction

Прототип мультиагентного планирования JSSP и воспроизводимый стенд сравнения правил.

Каждый заказ — JobAgent, каждый станок — MachineAgent, ManagerAgent собирает
ставки и запускает победившие операции через Environment. Среда разрешает старт
только на свободном станке после завершения предыдущей операции и поступления заказа.
Симуляционное время доходит до фактического завершения всех операций.

## Реализовано

- FIFO по времени входа в очередь станка, EDD, SPT, MWKR, Critical Ratio.
- ATC_LOCAL — явно описанная адаптация ATC к маршруту заказа.
- Исходная формула ставки и вариант ATC через агентов.
- Централизованные контрольные политики с теми же формулами.
- Синтетические сроки и поступления заказов поверх публичных статических данных.
- Проверки расписаний и парной эквивалентности, метрики, выгрузка результатов.
- Девять экземпляров JSPLIB, включая 100 заказов x 20 станков (2000 операций).

Поломки, цены, бюджеты, обучение и протокол Wellman пока не реализованы.
Пустые файлы в auction/ — задел, работающий однораундовый выбор находится в agents.py.

## Установка и запуск

Из корня репозитория:

```powershell
python -m pip install -e ".[dev]"
python -m pytest
python test_run.py
python scripts/download_benchmarks.py
python scripts/run_benchmarks.py
python scripts/plot_benchmarks.py
```

Если Python в Windows не подключается к GitHub, эквивалентный загрузчик:
`./scripts/download_benchmarks.ps1`.

Один экземпляр:

```powershell
python run_experiment.py data/benchmarks/ft10.txt
python run_experiment.py data/benchmarks/ft10.txt --scenario arrivals --due-factor 2 --seed 0
```

Число станков определяется автоматически; старый второй позиционный аргумент
поддерживается как проверка соответствия. Для ATC доступен параметр --k.

Сроков в исходных JSPLIB нет: отсутствие опоздания в статической задаче обозначается
N/A. Синтетические поступления не являются реальными производственными наблюдениями.
Оптимумы JSPLIB применяются только к исходной статической постановке.

Без сроков исходная ставка совпадает с MWKR, ATC_LOCAL — с SPT.
Агентная организация сама по себе не должна менять расписание при одинаковой
формуле приоритета: стенд проверяет это на каждом сценарии.

## Структура

- src/mas_jssp/environment — состояние, события и правила приоритета.
- src/mas_jssp/agents — ставки и однораундовый выбор.
- src/mas_jssp/metrics — метрики и независимая валидация.
- src/mas_jssp/experiments.py — сценарии и общая оценка методов.
- scripts/ — загрузка, массовый эксперимент и график.
- tests/ — проверки среды, агентов, формул, загрузки и воспроизводимости.
