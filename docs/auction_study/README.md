# Аукционы и CP-SAT: материалы для самостоятельного разбора

Эта папка посвящена новому этапу. Читать можно по порядку:

1. [Как устроены агенты и торги — с объяснением кода](01_agents_and_auctions.md).
2. [Как работает CP-SAT и почему это более сложный метод](02_cp_sat.md).
3. [Как установить и запустить сравнение](03_run_commands.md).
4. [Отчёт о выполненной проверке и результатах](04_results.md).
5. [Сохранённая таблица эксперимента](../../results/auction_protocols_v1/report.md).

Главное различие: **правило ставки**, **правило проведения торгов** и **метод поиска расписания** — разные части системы.

Новые торги используют условные кредиты. Это исследовательская модель: деньги не настоящие, нейросети нет, агенты не учатся. Их собственные бюджеты и локальные решения меняются по мере выполнения заказов.

Старый этап [Q-learning](../supervisor_report.md) и [локальные правила ATC](../local_rule_agents.md) сохранены отдельно. Результаты разных сценариев нельзя складывать в одну сравнительную таблицу.

## Карта кода

| Файл | Простое объяснение |
|---|---|
| [protocols.py](../../src/mas_jssp/auction/protocols.py) | Правила выбора победителя и оплаты одного аукциона |
| [budget_auction.py](../../src/mas_jssp/agents/budget_auction.py) | Заказы с собственными кредитами, станки и выполнение всей партии |
| [cp_scheduler.py](../../src/mas_jssp/cp_scheduler.py) | Построение математической модели расписания и запуск CP-SAT |
| [run_auction_comparison.py](../../scripts/run_auction_comparison.py) | Один общий эксперимент со всеми методами |
| [test_auction_protocols.py](../../tests/test_auction_protocols.py) | Проверки оплаты, бюджетов и завершения заказов |
| [test_cp_scheduler.py](../../tests/test_cp_scheduler.py) | Проверки оптимизатора на известных ответах и запрета просмотра будущего |

В новых файлах комментарии на русском объясняют назначение действий. Имена переменных на английском — обычное соглашение Python; далее они переведены в пояснениях.

Старые пустые файлы english_auction.py и vickrey_auction.py не используются. Реальные новые протоколы сосредоточены в protocols.py; это один общий интерфейс для честного сравнения.
