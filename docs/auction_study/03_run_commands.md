# 3. Как самому запустить проверку

Команды ниже предназначены для PowerShell. Их нужно выполнять из папки проекта.

## 1. На этом компьютере окружение уже подготовлено

Используйте именно его Python:

```powershell
.\.venv\Scripts\python.exe --version
```

Окружение — отдельная папка с библиотеками программы. Оно позволяет не менять библиотеки прежнего эксперимента с Q-learning. Папку .venv не отправляют на GitHub: на другом компьютере её создают заново.

Старое обычное python может не иметь OR-Tools. Это не ошибка алгоритма: тогда нужно пользоваться подготовленным окружением.

## 2. Один быстрый пример

```powershell
.\.venv\Scripts\python.exe scripts/run_auction_comparison.py data/benchmarks/ft06.txt --seeds 1 --output results/my_auction_demo_01
```

Что означает команда:

- python.exe — запускает Python;
- scripts/run_auction_comparison.py — файл, который организует сравнение;
- data/benchmarks/ft06.txt — задача: шесть заказов и шесть станков;
- --seeds 1 — один сценарий поступлений и сроков;
- --output — куда сохранить результат.

Папка результата должна быть новой. Повторный запуск с тем же output запрещён, чтобы не затереть измерения. Для следующего запуска укажите, например, my_auction_demo_02.

## 3. Все девять датасетов

```powershell
.\.venv\Scripts\python.exe scripts/run_auction_comparison.py data/benchmarks/ft06.txt data/benchmarks/ft10.txt data/benchmarks/ft20.txt data/benchmarks/la01.txt data/benchmarks/la16.txt data/benchmarks/la31.txt data/benchmarks/abz5.txt data/benchmarks/ta51.txt data/benchmarks/ta71.txt --seeds 3 --seed-base 420000 --cp-seconds 0.05 --offline-seconds 3 --output results/my_auction_all_01
```

Это 9 задач × 3 сценария × 12 методов = 324 попытки построения расписания. Офлайн-оптимизатор может не успеть найти допустимое решение; это явно фиксируется, а не скрывается.

Самые большие задачи требуют заметно больше времени. --cp-seconds ограничивает поиск одного вызова CP-SAT, а не время всего эксперимента. Построение модели и множество повторных вызовов тоже занимают время.

## 4. Что можно менять

| Параметр | Смысл | Начальное значение |
|---|---|---:|
| --seeds | Число случайных сценариев на каждый датасет | 3 |
| --seed-base | Первый номер сценария | 420000 |
| --scale | Число целых тактов в одной единице времени | 10 |
| --objective | Цель CP-SAT: tardiness или makespan | tardiness |
| --credits | Начальные кредиты на одну операцию заказа | 1 |
| --price-step | Шаг повышения цены | 0.1 |
| --max-rounds | Максимум раундов одних повышающихся торгов | 1000 |
| --cp-seconds | Лимит поиска при одном онлайн-перепланировании | 0.05 |
| --offline-seconds | Лимит поиска одного полного офлайн-расписания | 1 |

Для проведённого большого пилота лимит офлайн-поиска явно увеличен до 3 секунд.

Изменение --objective меняет цель оптимизатора, но не переписывает автоматически правила поведения аукционных агентов. Для сравнения по другой цели эти особенности нужно обсуждать отдельно.

Можно проверить бюджет 0: все заказы по-прежнему должны завершиться. Однако при нулевых ставках выбор будет определяться правилом разрешения равенств.

## 5. Где смотреть результаты

- report.md — таблица, с которой удобно начать.
- summary.json — общие средние, допустимость, сообщения и резервные решения.
- by_instance.json — отдельные средние по каждому датасету.
- runs.json — подробные результаты каждого метода на каждом сценарии.
- example_traces.json — шаги первого сценария для новых торгов и онлайн-CP.
- progress.jsonl — журнал, который пополняется после каждого выполненного запуска.
- config.json — параметры, версии и контрольные суммы исходников.

JSON — текстовый формат хранения данных. Его можно открыть обычным редактором. True означает «да», False — «нет», null — показатель отсутствует. Null не означает ноль.

Поле valid сообщает, прошло ли расписание проверку ограничений. Для неудачной попытки офлайн-поиска valid=false означает отсутствие найденного расписания, а не опубликованное расписание с нарушениями.

## 6. Проверки программы

```powershell
.\.venv\Scripts\python.exe -m pytest tests/test_environment.py tests/test_dispatch.py tests/test_adaptive_atc.py tests/test_local_rule_auction.py tests/test_auction_protocols.py tests/test_cp_scheduler.py -q
```

Это проверяет старую основу и публикуемые новые методы. Проверки кода не доказывают превосходство по качеству — для этого нужен эксперимент.

## 7. Установка на другом компьютере

Требуется Python 3.10 или новее. Использованная версия — Python 3.12.

```powershell
python -m venv .venv
.\.venv\Scripts\python.exe -m pip install -e ".[dev,optimization]"
```

OR-Tools зафиксирован в pyproject.toml на версии 9.14.6206. Для точного воспроизведения также учитывайте версии в config.json и реальное ограничение времени поиска.

На Windows необходим совместимый Microsoft Visual C++ Runtime. Во время подготовки на этом компьютере обнаружена старая MSVCP140.dll версии 14.36: оптимизатор аварийно завершался даже на минимальной задаче. Загрузка современной подписанной библиотеки 14.51 решила проблему.

Здесь применена только локальная настройка .venv: копия подписанной DLL в .venv/DLLs и загрузка из sitecustomize.py этого окружения. Системные файлы Windows не заменялись. Эта машинная настройка не входит в репозиторий.

На другом компьютере используйте [официальный установщик Microsoft Visual C++ Redistributable](https://learn.microsoft.com/en-us/cpp/windows/latest-supported-vc-redist). Не скачивайте отдельные DLL с неизвестных сайтов. Если обычный запуск решателя аварийно завершается без Python-ошибки, сначала проверяется окружение, а не меняется производственная модель.

## 8. Как не испортить исследование

Повторение прежних seed проверяет воспроизводимость. Для новых выводов после подбора параметров нужен заранее выделенный, ещё не просмотренный тест. Одно переименование папки результатов не создаёт новую тестовую выборку.

Архивы benchmark, adaptive_atc_v1 и local_rule_agents_v1 не изменяются. Новые результаты пишутся в отдельный output.
