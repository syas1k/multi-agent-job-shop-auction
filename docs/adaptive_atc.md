# Обучаемый агент выбора k для ATC

## Что добавлено

TabularKAgent — один обучаемый агент-координатор. На каждом событии он выбирает k
для всех аукционов текущего раунда. JobAgent рассчитывает ATC-ставку, MachineAgent
выбирает победителя, Environment запускает операции по прежним правилам.

Это минимальное расширение существующей системы. Оно не является распределённым
многоагентным RL: изучается польза адаптивного выбора параметра поверх агентной
схемы назначения. Цены, платежи, бюджеты и поломки не добавлялись.

Действия дискретные: k ∈ {0.5, 1.0, 1.5, ..., 5.0}. Табличному агенту не требуется
нейросеть. Единый k назначается всему раунду; независимый выбор k каждым станком
остаётся возможным последующим расширением.

## Наблюдение и ограничения модели

По доступным операциям вычисляются:

1. Средний относительный запас (d − t − R) / R.
2. Доля станков, недоступных для немедленного запуска.
3. Стандартное отклонение оставшегося времени до дедлайнов, делённое на среднюю
   длительность доступных операций.
4. Доля операций заказов с неположительным запасом d − t − R.
5. Число доступных операций на свободный станок.

Признаки дискретизируются в фиксированные интервалы; границы находятся в observation().
Они заданы до эксперимента и не обучаются на тесте. Всего возможно 432 состояния.

В наблюдение не входят заказы, ещё не поступившие в систему. Кандидаты ограничены
операциями, которые действительно можно запустить сейчас.

Полное состояние симулятора включает существенно больше информации, чем эти признаки.
Поэтому агрегированное наблюдение не гарантирует марковость. Практически это
частично наблюдаемая событийная задача с переменной длительностью шагов.
Теорема сходимости табличного Q-learning к оптимальной политике здесь не заявляется.

## Действие, переход и награда

После выбора k выполняются аукционы на доступных станках. Затем время продвигается
до следующего момента, когда можно принять решение, либо до завершения эпизода.

Обозначим через A(t) накопленное опоздание к моменту t:

A(t) = сумма max(0, min(t, C_j) − d_j).

Для ещё не завершённых заказов min(t, C_j) фактически равно t; для завершённых
накопление прекращается. Заказы до поступления исключены. В коде плановое окончание
последней операции всегда ограничивается текущим временем.

Награда:

r = −(A(t_next) − A(t)) / W,

где W — суммарная длительность обработки всех операций сценария.

Таким образом, сумма наград за эпизод точно равна −total_tardiness / W.
Это проверяется в каждом эпизоде и отдельными тестами, включая пересечение дедлайна
между событиями и прекращение штрафа после завершения заказа.

W используется только как постоянный масштаб награды/критерия для сценария,
а не как наблюдение агента или средство узнать будущие поступления.
Нормировка не позволяет крупным экземплярам автоматически доминировать
над маленькими при усреднении качества.

Используется gamma=1: не вводится дополнительное предпочтение откладывать штраф
только из-за дисконтирования. Эпизод заканчивается завершением всей конечной партии.

## Обучение

Обновление Q-таблицы:

Q(s,a) ← Q(s,a) + alpha × [r + max Q(s_next, ·) − Q(s,a)].

На терминальном переходе будущая ценность равна нулю.
Начальные Q равны нулю. Разные seed меняют исследовательские действия и порядок
учебных сценариев, а не начальные значения таблицы.

Epsilon линейно уменьшается с 0.3 до 0.05. На validation и test epsilon=0:
таблица, счётчики и параметры не обновляются.

Для неизвестного состояния используется лучший фиксированный k из validation.
При равенстве Q предпочтение также отдаётся этому действию, затем меньшему индексу.
При исследовательском действии k выбирается случайно из сетки.

По умолчанию проверяются alpha=0.1 и alpha=0.3, пять независимых seed на каждую alpha,
400 эпизодов обучения. Состояние модели оценивается на validation через 100 эпизодов.
Это выбор лучшего checkpoint, не досрочное прекращение вычислений.

## Разделение данных

Начальный эксперимент использует фиксированную панель ft06, ft10, ft20, la01, la16.
Маршруты и длительности JSPLIB общие между выборками; проверяется перенос на новые
поступления и сроки, а не на неизвестные маршруты или размеры задач.

На каждый экземпляр:

| Выборка | Seed | Количество сценариев |
|---|---|---:|
| Train | 10000–10079 | 80 |
| Validation | 20000–20009 | 10 |
| Test | 30000–30029 | 30 |

Итого 400/50/150 сценариев. Диапазоны не пересекаются.
Из комбинации имени экземпляра, seed и имени потока через SHA-256 получаются
раздельные генераторы поступлений и дедлайнов.

Поступления равномерны на [0, total_processing / number_of_machines].
Для каждого заказа коэффициент срока независимо выбирается равномерно на [1.2, 2.8]:
d = release_time + factor × job_processing.

Это новая версия генератора сценариев. Её результаты нельзя напрямую сравнивать
с прежним отчётом, где коэффициент срока был постоянным для всей партии.
Сценарии по-прежнему синтетические, не данные реального предприятия.

## Честный фиксированный baseline и выбор моделей

1. Фиксируется protocol.json: выборки, параметры, критерий, версии исходного кода,
   версия/хеш метаданных датасета.
2. Фиксированный ATC прогоняется на validation для всех десяти k.
3. Выбирается один k с минимальным средним normalized_tardiness.
4. На train обучаются пять моделей для каждой alpha. Для каждого запуска выбирается
   лучший checkpoint по validation.
5. В качестве checkpoint 0 участвует пустая таблица с фиксированным лучшим k.
   Это заранее заданная возможность отказаться от ухудшившегося обучения.
6. Одна общая alpha выбирается по среднему validation-результату пяти запусков.
7. Сохраняется selection.json с k, alpha, checkpoint и хешами пяти моделей.
8. Только затем загружается test.

Фаза обучения не загружает тестовые сценарии. После открытия теста повторное
обучение в той же папке запрещено. Хеши протокола, выбранных моделей и исходников
проверяются перед тестом. Повторное сохранение итогового теста поверх старого запрещено.

В models/ сохраняются как выбранные по validation модели, так и окончательные
обученные таблицы с суффиксом _last. Последние не используются для выбора по тесту.
Если выбран episode=0, это отсутствие подтверждённой пользы обучения на validation.
Такая модель не должна описываться как успешный обученный планировщик.

## Статистика

Основной предзаданный критерий — normalized_tardiness = total_tardiness / W.

На тесте каждую из пяти выбранных моделей сравниваем с фиксированным ATC на одних
и тех же 150 сценариях. Baseline выполняется один раз на сценарий; всего 900 расписаний.

Сохраняются:

- среднее основного критерия и сырых метрик;
- SD средних по пяти независимым обучениям;
- SD средних по 30 блокам seed сценариев;
- 95% bootstrap CI средних и парной разности Q − ATC;
- двусторонний Wilcoxon по основному критерию;
- выбранные k, доля неизвестных состояний и количество решений с конкуренцией.

Нельзя считать 5 × 150 результатов агента независимыми наблюдениями.
Для Wilcoxon показатели сначала усредняются по моделям и фиксированным экземплярам:
остаётся одна парная разность на каждый из 30 seed.
Разности округляются до 12 знаков, нули обрабатываются методом Pratt.
Если все разности нулевые, результат явно задаётся как p=1.

Для bootstrap независимо пересэмплируются строки обучения и блоки seed сценариев,
при этом все экземпляры панели остаются вместе. Используются 5000 повторов и
фиксированный seed статистики 7401. Панель бенчмарков считается фиксированной.

Wilcoxon предполагает симметричность распределения парных разностей и условен
на данном наборе обученных политик. При пяти запусках обучения интервалы следует
считать предварительными. Для makespan и сырого опоздания приведена описательная
статистика, дополнительные подтверждающие p-value не публикуются.

Изменение в процентах в новом отчёте — отношение средних:
100 × (mean_Q − mean_ATC) / mean_ATC.
Это отличается от усреднения процентов отдельных сценариев в старом отчёте.

## Самостоятельный запуск

Из корня проекта, Python 3.10+:

```powershell
python -m pip install -e ".[dev,learning]"
python -m pytest
python scripts/run_learning_experiment.py --output results/adaptive_atc_new
python scripts/plot_learning_experiment.py --results results/adaptive_atc_new
```

Все этапы можно выполнять отдельно, используя одну новую папку:

```powershell
python scripts/run_learning_experiment.py --phase prepare --output results/new_study
python scripts/run_learning_experiment.py --phase train --output results/new_study
python scripts/run_learning_experiment.py --phase test --output results/new_study
```

Параметры задаются на этапе prepare; train/test используют сохранённый protocol.json,
а не новые значения командной строки.

Быстрый технический прогон, непригодный для содержательных статистических выводов:

```powershell
python scripts/run_learning_experiment.py --output results/learning_smoke --instances ft06 --train-seeds 4 --val-seeds 2 --test-seeds 2 --episodes 10 --checkpoint-every 5 --runs 2 --alphas 0.1
```

Применение уже сохранённой модели без обучения (путь модели брать из selection.json):

```powershell
python scripts/run_adaptive_agent.py data/benchmarks/ft10.txt --model results/adaptive_atc_v1/models/q_alpha0.1_seed102.json --seed 30000
```

Имя модели в примере зависит от выбранной alpha. Оценка использует новый генератор
learning_data.py; seed из старого run_experiment.py создаёт другой сценарий.

Основные файлы: protocol.json, validation_grid.csv, training_history.csv,
selection.json, models/, test_started.json, test_runs.csv, test_summary.json, report.md.

Не следует повторно подбирать параметры по уже прочитанному тесту.
Для следующей исследовательской итерации нужен новый закрытый тест; просто новая
папка с теми же seed не создаёт новый независимый тест.

## Источники и интерпретация

- [Watkins, Dayan (1992), Q-learning](https://www.gatsby.ucl.ac.uk/~dayan/papers/wd92.html):
  базовый алгоритм. Условия теоремы сходимости не переносятся автоматически
  на наше агрегированное наблюдение.
- [SciPy: wilcoxon](https://docs.scipy.org/doc/scipy/reference/generated/scipy.stats.wilcoxon.html):
  парная проверка, нулевые разности и ограничения интерпретации.
- Базовая формула ATC и её адаптация описаны в methods_and_sources.md.

Если табличный агент не улучшит результат, это вывод о данном наблюдении,
пространстве действий, награде и бюджете обучения. Он не доказывает, что
нейросеть не сможет дать улучшение. Аналогично положительный результат на этой
панели не доказывает универсальное преимущество RL или аукционного механизма.
